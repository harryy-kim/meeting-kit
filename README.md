# meeting-kit

외국어 미팅을 위한 **실시간 캡처 분석 + 종합 분석 + 발표 자료** Claude Code 플러그인.

세 가지 축으로 미팅을 완벽하게 따라잡고, 정리하고, 공유합니다:

1. **🔴 실시간 분석** — 매 캡처마다 즉시 짧은 분석. 미팅 중 흐름을 놓치지 않게.
2. **📘 종합 분석** — 미팅 종료 후 전체 흐름·결정·용어·다이어그램을 한 문서로 정리.
3. **🎤 발표 자료** — 사내 공유용 슬라이드(deck) + 발표 대본(script)을 자동 생성.


## 왜 만들었나

일본어/중국어/영어 미팅에 참여할 때 겪는 두 종류의 고통:

**미팅 중**:
- 실시간 번역기는 딜레이가 있고, 전문 용어를 자주 오인한다
- 화면 자료가 어렵고 빠르게 넘어간다
- **흐름을 잠깐 놓치면 따라잡기 힘들다**

**미팅 후**:
- 캡처한 텍스트가 너무 많아서 다시 읽기 부담스럽다
- 결정 사항·열린 질문·새 용어가 발화 사이에 흩어져 있어 한눈에 안 보인다
- 동료에게 공유할 정리본이 필요한데 손으로 만들기 비효율
- 같은 미팅 시리즈에서 같은 용어가 반복되는데 매번 검색해야 한다

이 플러그인은 두 시점 모두에서 마찰을 줄입니다.

- **실시간**: 매 캡처마다 5~7줄 분석이 자동으로 따라옴 — 요지/새 용어/번역 오인/맥락
- **미팅 후**: `/meeting-review` 한 번이면 전체 미팅을 종합 분석한 `analysis.md` 생성 — 사진 embed + mermaid 다이어그램 + 용어 사전 + 결정/액션 정리

## 구성

### 스킬 (사용자 명령)

| 명령 | 용도 | 사용 시점 |
|---|---|---|
| **`/cap` + 이미지/텍스트** | **저장 + 실시간 분석** ⭐ | **미팅 중 매번** |
| **`/meeting-review [name]`** | **미팅 종합 분석** ⭐ | **미팅 종료 후** |
| **`/deck [name]`** | **사내 공유용 발표 슬라이드 생성** ⭐ | **공유 자료 필요할 때** |
| **`/script [name] [--duration N]`** | **발표 대본 생성** ⭐ | **발표 직전 리허설** |
| `/cap new {name}` | 새 미팅 시작 | 미팅 시작 시 |
| `/cap context ...` | 미팅 배경 정보 저장 | 미팅 시작 직후 (선택) |
| `/ask {질문}` | 명시적 질문 (캡처 없이) | 질문만 따로 할 때 |
| `/recap` | 누적 흐름 요약 | 흐름 크게 놓쳤을 때 |
| `/glossary` | 누적 용어 사전 관리 | 언제든 |
| `/meetings` | 미팅 목록 + 활성 상태 | 언제든 |

⭐ = 플러그인의 핵심 기능. 미팅 중·미팅 후·공유 단계를 각각 책임진다.

### 에이전트 (서브에이전트, 자동 호출)

| 에이전트 | 호출자 | 역할 |
|---|---|---|
| `meeting-analyzer` | `meeting-review` | 미팅 폴더 전체를 읽고 analysis.md 작성 (사진 embed + mermaid 다이어그램) |
| `deck-builder` | `deck` | context/analysis/notes/images 모두 종합하여 사내 공유용 deck.md 생성 |
| `script-writer` | `script` | deck.md를 입력으로 발표자 구어체 대본 script.md 생성 |
| `glossary-extractor` | `glossary extract` | notes.md에서 전문 용어 추출하여 _glossary.md에 병합 |

에이전트는 별도 컨텍스트에서 무거운 작업을 처리하여 메인 세션을 보호한다.

```
~/meetings/
├── .current                           # 활성 미팅 폴더 경로 (단일 라인)
├── _glossary.md                       # 누적 용어 사전 (모든 미팅 공유)
│
├── 2026-04-07-mitsui-q2/
│   ├── notes.md                       # 캡처 (시간순 슬라이드 + 발화)
│   ├── context.md                     # 미팅 배경 (선택, 채우면 분석 품질 ↑)
│   ├── analysis.md                    # /meeting-review 결과
│   ├── deck.md                        # /deck 결과 (사내 공유 슬라이드, Marp 호환)
│   ├── script.md                      # /script 결과 (발표 대본)
│   └── images/
│       ├── slide-01.png
│       └── slide-02.png
│
└── 2026-04-08-mitsui-q3/
    └── ...
```

## 사용 흐름 (예시)

### 미팅 시작

```
사용자: /cap new mitsui-q2

→ 📁 새 미팅 시작 — ~/meetings/2026-04-07-mitsui-q2
  💡 배경 정보 있으면 /cap context ... 또는 자연어로 알려주세요 (선택)

사용자: 이 미팅은 일본 Payroll 신규 도입 리뷰고, 나는 한국 쪽 PM이야. Guest-9는 토미오카씨 (Varit 담당 개발자).

→ 📋 context 저장됨
```

### 미팅 중 캡처 (저장 + 즉시 분석)

```
사용자: [스크린샷 드래그] /cap

→ 📸 슬라이드 01 저장 (13:31)

  📊 슬라이드: Calcu 영역 초기 도입 플로우 (요건 정의~사양 설계 단계)
  💭 요지: 발표자가 Varit 설계 프로세스를 소개하려는 시점

사용자: /cap 변동 데이터는 그 달에만 쓰는 데이터를 의미한다고 함

→ 📝 추가 → 슬라이드 01 (13:33)

  💭 요지: Varit이 다루는 "변동 데이터"의 정의 — 단발성 월별 데이터
  🆕 새 용어: 変動データ (월별 변동 데이터, 예: 특별 수당/근태)
              ← 글로서리 적립하려면 /glossary add

사용자: /cap この機能は実は経産省じゃなくて計算仕様書のことです

→ 📝 추가 → 슬라이드 01 (13:35)

  💭 요지: 앞 발화 정정 — "경산성"이 아니라 "계산 사양서"
  ⚠️ 번역 의심: "경산성/경산" → 실제 "計算 사양서" (経産↔計算 한자 동음 오인)
```

분석 항목은 해당 사항이 있을 때만 출력. 새 용어 없으면 🆕 줄 생략 등.

### 미팅 중간 요약

```
사용자: /recap

→ 📍 현재 슬라이드: 5장 / 발화 12블록 (13:29~14:15)
  지금까지 흐름:
  1. 테스트 방식 논의 (실데이터 기반 시뮬레이션)
  2. 기능 범위 — 어디까지 커버할지 미결
  3. Varit 설계 프로세스 설명 ← 지금
  🔑 핵심: Varit은 경산 사양서 확정 후 착수
```

### 미팅 종료 후 종합 분석

미팅 후에는 캡처한 모든 자료(notes.md + context.md + 슬라이드 이미지)를 종합한 `analysis.md` 한 문서를 자동 생성합니다. 미팅 흐름 복습, 동료 공유, 다음 미팅 준비에 사용.

```
사용자: /meeting-review

→ (meeting-analyzer 에이전트 호출)
  ✅ 분석 완료 → ~/meetings/2026-04-07-mitsui-q2/analysis.md

  - 한 줄 요약: Calcu 영역의 Varit/Output 설계 방식 리뷰 + 기능 범위 조율
  - 토픽: 6개
  - 결정: 4개
  - 미결 질문: 3개
  - 새 용어: 18개
  - 다이어그램: 2개 (시스템 관계도, Varit 설계 흐름)
```

생성되는 `analysis.md`에 포함:
- **한 줄 요약** + **Executive Summary**
- **토픽별 핵심 내용** (관련 슬라이드 이미지 자동 embed)
- **🎨 mermaid 다이어그램** — 시스템 관계도, 프로세스 흐름 등 (구조가 복잡할 때)
- **용어 사전** (이 미팅 등장)
- **주요 결정 사항** + **열린 질문**
- **번역기 오인 정리** (가장 가치 높은 메타데이터)
- **다음 액션 Top 3-5**

→ 동료에게 공유 가능한 한 문서로 미팅 결과가 정리됨.

### 사내 공유 발표 자료 만들기

종합 분석(analysis.md)이 나온 뒤, 사내 공유용 슬라이드와 대본을 자동 생성합니다.

```
사용자: /deck

→ (deck-builder 에이전트 호출)
  ✅ 발표자료 작성 완료 → ~/meetings/2026-04-07-mitsui-q2/deck.md
  - 슬라이드: 11장 (약 11분)
  - 사용한 이미지: 4장
  - 핵심 인용: 6개
  - 결정: 4개 / 액션: 3개

  💡 다음: /script 으로 발표 대본도 생성할 수 있습니다.

사용자: /script --duration 15

→ (script-writer 에이전트 호출)
  ✅ 발표 대본 작성 완료 → ~/meetings/2026-04-07-mitsui-q2/script.md
  - 슬라이드 대본: 11개
  - 목표 발표 시간: 약 15분
  - 강조 포인트: 11개
  - 예상 질문: 5개

  💡 발표 전 한 번 소리 내어 읽어보시길 권합니다.
```

deck.md는 Markdown(Marp 호환). Marp가 설치돼 있으면 `marp deck.md --pdf`로 PDF 변환 가능. 없어도 일반 마크다운으로 그대로 읽힙니다.

script.md는 슬라이드별로 본문(구어체 존댓말) + 강조 포인트 + 전환 멘트 + 예상 질문 + 시간 배분이 포함된 발표 대본입니다.

### 용어 누적

```
사용자: /glossary extract

→ (glossary-extractor 에이전트 호출)
  ✅ 추출 완료
  - 새로 추가: 18개
  - 정의 보강: 0개
  - 총 용어: 18개

사용자: /glossary search Varit

→ Varit (バリット): 월별 변동 데이터 입력 영역
   첫 출현: 2026-04-07-mitsui-q2 (슬라이드 01, 13:31)
   번역기 오인: "바리트", "발리섬", "バリ島"
```

## 세 축의 차이

| 축 | 시점 | 출력 | 용도 |
|---|---|---|---|
| **🔴 실시간 분석** (`/cap`) | 미팅 진행 중, 매 캡처마다 | 채팅창 5~7줄, 즉시 (~1초) | 흐름 따라잡기, 즉각 컨텍스트 |
| **📘 종합 분석** (`/meeting-review`) | 미팅 종료 후 명시 호출 | analysis.md 파일, 다이어그램 포함 | 복습, 본인 정리, 다음 미팅 준비 |
| **🎤 발표 자료** (`/deck` + `/script`) | 분석 완료 후 공유 단계 | deck.md (슬라이드) + script.md (대본) | 사내 공유, 동료 브리핑, 리허설 |

세 축은 보완 관계입니다. 실시간은 **순간을 살리고**, 종합은 **전체를 정리하고**, 발표 자료는 **남에게 전달합니다**.

## 응답 길이 원칙

각 스킬의 응답 길이는 사용 시점에 맞춰져 있습니다:

- **`cap`** (저장 + 실시간 분석): **15~25줄** — 짧은 불릿 위주로 스캔 가능
- **`ask`, `recap`**: **5줄 이내**
- **`/cap new`, `/cap context`**: **1~2줄**
- **`meeting-review`**: **장문 OK** — 미팅 후 한 문서로 정리되는 것이 본질
- **`deck`, `script`**: **인라인 짧게 (3~6줄), 결과는 파일로** — 사용자가 파일 직접 열어 확인

## 디자인 결정

- **두 분석 축**: 실시간(인라인)과 종합(에이전트)을 명확히 분리. 각각의 시점·길이·깊이가 다르기 때문.
- **상태 추적**: `~/meetings/.current` 단일 파일로 활성 미팅 추적. 단순함이 신뢰성을 만든다.
- **에이전트 분리**: 종합 분석은 서브에이전트에 위임하여 메인 컨텍스트를 보호. 미팅 진행 중 캡처 흐름이 끊기지 않는다.
- **번역기 오인 표시**: 사용자가 외국어 번역에 의존하므로 가장 가치 있는 메타데이터. 양쪽 분석 모두에서 우선 노출.
- **다이어그램 자동 생성**: 종합 분석에서 시스템 관계나 프로세스가 복잡하면 mermaid 다이어그램으로 시각화.
- **글로서리 누적**: 같은 미팅 시리즈에서 이해도가 누적되도록. 실시간/종합 분석 모두 글로서리를 참조·갱신.

## 로드맵 (잠재적 v0.3+)

- `/cap end` — 미팅 명시적 종료 (종료 시각 기록)
- `/cap fix` — 번역기 오인 구간 사후 보정
- `/cap export` — Obsidian/PDF/Notion 내보내기
- `/cap prep` — 다음 미팅 전 관련 과거 미팅 자동 브리핑
- context 상속 (`/cap new mitsui-q3 --inherit mitsui-q2`) — 같은 시리즈 미팅
- 자동 글로서리 추출 (capture 시 백그라운드)
