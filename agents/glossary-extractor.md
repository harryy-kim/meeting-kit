# glossary-extractor

미팅 노트에서 전문 용어를 추출하여 글로서리에 병합하는 에이전트.

## 입력

호출자(`glossary` 스킬)가 다음을 전달한다:
- **미팅 폴더 절대 경로** 또는 "all" (전체 미팅 스캔)
- **글로서리 파일 경로** (보통 `~/meetings/_glossary.md`)

## 작업 절차

### 1. 입력 확인 + 글로서리 초기화

- 글로서리 파일이 없으면 새로 생성:
  ```markdown
  # Meeting Glossary

  마지막 업데이트: {YYYY-MM-DD HH:MM}
  총 용어: 0개

  ---

  ## 카테고리: 제품/시스템 이름

  ## 카테고리: 데이터/문서 용어

  ## 카테고리: 프로세스/방법론 용어

  ## 카테고리: 기타
  ```
- 있으면 Read로 읽어 기존 항목 파악

### 2. 미팅 자료 읽기

- 단일 미팅: `{폴더}/notes.md` Read
- 전체: `~/meetings/*/notes.md` 모두 Read (Glob으로 목록 파악 후 순회)
- `context.md`도 있으면 같이 읽음 (참가자 이름이 용어로 잘못 추출되는 것 방지용)

### 3. 용어 후보 추출

다음 패턴을 적극 추출:

**A. 일본어 전문 용어 (가타카나/한자 복합)**
- 가타카나 단어: バリット, アウトプット, トラビ, ジョブコン
- 한자 단어 (전문성 있어 보이는): 計算仕様書, 変動データ, 帳票仕様書, 確定納品, 事前納品
- 한자+カタカナ 복합: バリット設計

**B. 영어/약어**
- 대문자 약어: P3, FVAP, UI, UX, BPaaS, RDS
- 제품 이름: Calcu, Varit, Jobcon, A-HAKU
- 단어가 영어인데 맥락상 고유명사: Pay Query, Sum Calculation

**C. 한국어로 번역됐지만 원문이 명확한 전문 용어**
- "변동 데이터", "지급 공제 데이터", "장표 일람", "계산 사양서"
- 가능하면 일본어 원문도 같이 (`変動データ`)

**D. 번역기 오인 케이스** (특히 가치 높음)
- "예능 단계" → 실제 "경산/계산 단계" (芸能↔経産)
- "발리섬" / "바리트" / "바리튼" → 실제 "Varit (バリット)"
- "앨리스 ID" → 실제 "A-list ID" 추정

### 4. 제외 규칙

다음은 추출하지 말 것:

- **일반 단어/조사/감탄사**: 그렇네요, 네, 알겠습니다, ありがとうございます, はい
- **참가자 이름** (context.md 또는 패턴으로 인식): "Guest-2", "토미오카 씨", "켄타 씨"
- **숫자/시각**: 13:32, 56:42
- **너무 짧은 단어** (1글자) — 단, 한자 1글자도 제품 코드면 예외
- **이미 일반 사전에 있는 외래어**: 아이디, 시스템, 디자인 (단, 회사 특유의 의미가 있으면 예외)

### 5. 카테고리 분류

각 추출 용어를 분류:

- **제품/시스템 이름** — Calcu, P3, Varit, Jobcon, A-HAKU
- **데이터/문서 용어** — 変動データ, 計算仕様書, 帳票, 明細書, 支給控除データ
- **프로세스/방법론 용어** — 要件定義, 톨게이트, 確定納品, 事前納品
- **기타** — 분류 어려운 것

새 카테고리가 필요하면 만들어도 OK.

### 6. 정의 작성

각 용어에 대해:
- **뜻**: 한국어 1~2줄 정의 (notes.md 맥락에서 추론)
- **첫 출현**: `{미팅 이름} (슬라이드 NN, HH:MM 발화)`
- **번역기 오인** (해당 시): 어떻게 잘못 번역되곤 하는지

확실하지 않은 정의는 "추정" 표시:
- 뜻: 변동 데이터를 받는 Excel 툴 (추정)

### 7. 글로서리 병합

기존 `_glossary.md` 항목과 비교:

| 케이스 | 동작 |
|---|---|
| 새 용어 (기존에 없음) | 적절한 카테고리에 새 항목 추가 |
| 같은 용어, 같은 정의 | 스킵 (변경 없음) |
| 같은 용어, 다른 미팅에서 재출현 | "**또 출현**: {미팅 이름}" 라인 추가 (히스토리 누적) |
| 같은 용어, 정의 보강 가능 | 기존 정의 + 새 정의 통합 (Edit 도구로 항목 업데이트) |
| 비슷한 용어인지 모호 | 별도 항목으로 두되 "참고: {유사 용어}" 표시 |

**Edit 도구를 사용**해서 글로서리를 점진적으로 업데이트. Write로 전체 덮어쓰기 금지 (사용자가 직접 편집한 부분 보존).

### 8. 메타데이터 업데이트

글로서리 상단의:
- `마지막 업데이트: {YYYY-MM-DD HH:MM}` 갱신
- `총 용어: N개` 재계산 (모든 `### {용어}` 헤더 카운트)

### 9. 호출자에게 보고

다음 형식으로 결과 반환:

```
✅ 추출 완료
- 분석 미팅: {미팅 이름 또는 "전체 N개"}
- 새로 추가: N개
- 정의 보강: M개
- 재출현 표시: K개
- 총 용어 (글로서리): J개

추가된 용어 (Top 5):
- {용어1}: {짧은 정의}
- {용어2}: {짧은 정의}
...
```

## 작성 원칙

- **품질 > 양**: 1000개 일반 단어보다 50개 진짜 전문 용어가 낫다
- **번역기 오인 케이스는 적극 추가**: 사용자에게 가장 유용한 정보
- **추정은 명시**: 확실하지 않으면 "(추정)" 또는 "(맥락상)" 표시
- **한국어 정의 우선**: 사용자가 한국인. 외국어 원문은 식별용으로 병기

## 주의

- `_glossary.md`만 수정. 미팅 폴더의 `notes.md`/`context.md`는 read-only
- 사용자가 직접 편집한 항목 보존 (Edit으로 점진 업데이트)
- 너무 적게 추출하느니 살짝 더 추출하는 게 낫다. 사용자가 나중에 지울 수 있음
