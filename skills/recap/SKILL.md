# recap — Live Mid-Meeting Recap

미팅 중 빠른 따라잡기를 위한 짧은 요약 스킬.

## 언제 사용하나

- 미팅 흐름을 잠깐 놓쳤을 때 (번역 딜레이로 따라가기 힘들었거나, 잠시 다른 일 했을 때)
- "지금 어디까지 왔지?" 빠른 위치 확인
- `/meeting-review`(전체 분석)는 너무 무겁고 시간이 걸릴 때

## 동작

### 1. 활성 미팅 찾기

`~/meetings/.current` 읽기. 없으면: `⚠️ 활성 미팅 없음` 한 줄.

### 2. 빠른 컨텍스트 수집

활성 미팅 폴더에서:
- `notes.md` 전체 (또는 너무 길면 마지막 ~300줄)
- `context.md` (있으면) — 미팅 주제 1줄 정도만 활용

이미지는 읽지 않는다 (속도 우선).

### 3. 짧은 요약 출력

다음 형식으로 **5줄 이내** 출력:

```
📍 현재 슬라이드: {NN}장 / 발화 {M}블록 ({시작}~{최근시각})

지금까지 흐름:
1. {토픽 1 — 한 줄}
2. {토픽 2 — 한 줄}
3. {토픽 3 — 한 줄, 진행 중이면 "← 지금" 표시}

🔑 핵심 포인트: {가장 중요한 한 가지}
```

토픽 개수는 내용에 따라 2~5개 사이. 너무 많으면 압축.

## 응답 길이 (매우 중요)

**5줄 이내**. 미팅 중에 화면을 길게 못 본다.

- ✅ 5줄짜리 깔끔한 요약
- ❌ 토픽별 자세한 설명, 인용, 제안

자세한 분석이 필요하면 사용자가 명시적으로 `/meeting-review`를 부르도록 안내 한 줄:
```
💡 자세한 분석은 `/meeting-review`
```

## 엣지 케이스

| 상황 | 대처 |
|---|---|
| 활성 미팅 없음 | 한 줄 안내 후 종료 |
| `notes.md`가 너무 짧음 (슬라이드 0개, 발화 1개) | "📍 아직 캡처가 충분하지 않습니다" |
| `notes.md`가 너무 김 (수만 줄) | 마지막 ~300줄만 읽어 "최근 흐름"으로 요약 |

## 주의

- **빠른 응답이 핵심**. 절대 무거운 작업하지 말 것
- 파일 수정 금지 (read-only)
- 사용자가 자세한 걸 원하면 `/meeting-review`로 위임
