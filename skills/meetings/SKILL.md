# list — Meeting Index

`~/meetings/` 안의 모든 미팅을 한눈에 보여주는 스킬.

## 동작

### 1. 활성 미팅 확인

`~/meetings/.current` 읽기 (있으면 해당 폴더 경로).

### 2. 미팅 폴더 스캔

`~/meetings/` 디렉토리에서 `YYYY-MM-DD-*` 패턴의 폴더를 모두 찾는다.
(언더바로 시작하는 파일/폴더는 제외 — 예: `_glossary.md`, `.current`)

각 폴더에 대해:
- **이름**: 폴더명 (또는 `notes.md` 첫 줄에서 `# 미팅 — {name}` 추출)
- **시작 시각**: `notes.md`의 `- 시작:` 라인
- **슬라이드 수**: `images/slide-*.png` 개수
- **발화 블록 수**: `notes.md`에서 `### [HH:MM] 발화` 패턴 카운트
- **분석 여부**: `analysis.md` 존재 유무
- **context 채워졌는지**: `context.md` 존재 + 빈 템플릿 이상의 내용이 있는지

### 3. 출력 형식

```
📅 미팅 목록 ({N}개)

| 활성 | 날짜       | 이름            | 시작  | 슬라이드 | 발화  | 분석 | Ctx |
|------|-----------|----------------|------|---------|------|------|-----|
| ⭐   | 2026-04-07 | test           | 13:29 | 2장      | 4    | ✅    | -   |
|      | 2026-04-05 | mitsui-q1      | 14:00 | 8장      | 23   | ✅    | ✅  |
|      | 2026-03-30 | onboarding     | 10:30 | 3장      | 7    | -    | -   |

총 용어 (글로서리): {K}개
```

### 4. 추가 정보

목록 아래에 한 줄 안내:
```
💡 분석: /meeting-review {이름}  |  활성 변경: /cap new {이름}
```

## 인자 처리

- **인자 없음** → 전체 목록
- **`list active`** → 활성 미팅의 상세 정보 한 페이지 (이름, 경로, 슬라이드/발화 수, 마지막 캡처 시각)
- **`list recent N`** → 최근 N개만

## 응답 길이

- 표 + 1~2줄 안내. 5~10줄 내외.
- 미팅이 너무 많으면 (>20개) 최근 10개만 표시 + "더 보려면 `list all`" 안내

## 엣지 케이스

| 상황 | 대처 |
|---|---|
| `~/meetings/`가 없음 | "미팅이 아직 없습니다. `/cap new {이름}`으로 시작하세요." |
| 미팅 폴더 0개 | 위와 동일 |
| 폴더 구조가 깨진 미팅 (notes.md 없음) | 표에 표시하되 "⚠️ 손상" 마크 |
| 매우 많은 미팅 (>50) | 최근 10개 + 총 개수 표시 |

## 주의

- 디렉토리/파일 스캔만. 절대 수정하지 말 것 (read-only)
- 빠른 응답 우선. 분석 등 무거운 작업 X
