# ask — Live Q&A

미팅 중 빠른 질문에 답하는 스킬. 메인 세션에서 직접 처리하여 응답 지연을 최소화한다.

## 언제 사용하나

- 미팅 중 번역기가 놓친 전문 용어, 맥락, 약어를 즉시 해소하고 싶을 때
- "방금 그 ~ 뭐였지?", "지금 무슨 얘기 중이야?" 같이 빠른 답이 필요할 때
- `review`(전체 분석)는 무겁고 `recap`(중간 요약)은 너무 일반적일 때 — 구체적 질문 전용

## 동작

### 1. 활성 미팅 찾기

`~/meetings/.current` 읽기. 없으면: `⚠️ 활성 미팅 없음. 일반 질문으로 답하시겠어요?` 한 줄 안내 후, 사용자가 OK 하면 일반 답변.

### 2. 컨텍스트 수집 (가볍게)

활성 미팅 폴더에서 다음을 읽는다 (필요한 만큼만):

1. **`context.md`** — 미팅 배경 (참가자, 주제, 사용자 역할 등). 답변 톤을 맞추는 데 사용.
2. **마지막 슬라이드 이미지** — `images/slide-{최대번호}.png`. 시각적 맥락이 질문과 관련 있어 보이면 Read 도구로 이미지 자체를 읽어 분석.
3. **최근 발화** — `notes.md`의 마지막 1~3개 슬라이드 섹션 (대략 마지막 100~200줄). 너무 많이 읽지 말 것 — 빠른 응답이 우선.

### 3. 답변

사용자 질문에 **한국어로 간결하게** 답한다. 형식:

- **짧은 답**: 1~3문장이면 끝나는 질문은 그렇게
- **용어 질문**: `**{용어}**: {정의 1줄} ({맥락 1줄})` 식
- **맥락 질문**: 최근 발화에서 관련 부분을 인용 + 해석
- 답이 불확실하면 명시: "확실하지 않지만, 맥락상 ~인 것 같습니다"

### 4. 후속 동작

답변 후, 사용자가 그 용어/내용을 **글로서리에 저장하고 싶어 할 가능성**이 있으면 한 줄 제안:
```
💡 이 용어를 글로서리에 저장하려면 "글로서리에 추가" 라고 하세요
```
(매번 제안하지 말 것 — 처음 보는 전문 용어 / 사용자가 명확히 학습 의도 있어 보일 때만)

## 응답 길이

- 사용자는 미팅 중. **5줄 이내**가 이상적.
- 단, 사용자가 "자세히 설명해줘" 같이 명시하면 길어도 OK.

## 엣지 케이스

| 상황 | 대처 |
|---|---|
| 활성 미팅 없음 | 일반 질문으로 답할지 묻기 |
| 마지막 슬라이드 이미지 없음 | 텍스트 발화만으로 답변 |
| 질문이 너무 광범위 (예: "이 미팅 뭐야") | "전체 분석은 `/review`를 쓰세요" 안내 + 짧은 한 줄 답 |
| 답을 모름 | 솔직히 모른다고 답함. 추측을 사실처럼 말하지 말 것 |

## 주의

- **빠른 응답이 핵심**. 무거운 분석/긴 응답은 이 스킬의 책임이 아님 → `review`로 위임
- `notes.md`나 `context.md`를 절대 수정하지 말 것 (read-only)
- 사용자 질문이 캡처 의도면 (예: 텍스트 붙여넣기) → `cap` 스킬로 라우팅
