# cap — Meeting Capture

미팅 중 화면 스크린샷과 실시간 번역 텍스트를 페어로 묶어 저장하는 스킬.

## 사용자가 무엇을 하려는지

외국어(주로 일본어) 미팅에 참여 중이고, 실시간 번역 앱을 통해 텍스트로 번역된 발화를 약간의 딜레이로 받는다. 발표 화면의 자료가 어렵기 때문에:

1. **화면 스크린샷을 보존** — 자료 자체
2. **그 화면을 보면서 발화된 번역 텍스트를 같이 묶어** 저장 — 한 화면에 여러 발화가 누적
3. 나중에 다시 보거나 `meeting-review` 스킬로 분석

**목표**: 마찰 없이 캡처를 받아 깔끔한 시간순 노트로 정리하는 것. 사용자는 미팅 중이라 화면을 길게 못 보므로 **응답은 항상 1~2줄**.

## 동작 모드

사용자 메시지의 내용으로 모드를 자동 판별한다.

### 모드 1: 새 미팅 시작 — `/cap new {meeting-name}`

예: `/cap new mitsui-q2-review`

1. `~/meetings/{YYYY-MM-DD}-{slug}/` 디렉토리 생성
   - slug = meeting-name을 소문자/하이픈으로 정규화 (한글은 그대로)
   - 같은 날 같은 이름이 이미 있으면 `-2`, `-3` 접미사
2. 그 안에 `images/` 서브디렉토리 생성
3. `notes.md` 초기화:
   ```markdown
   # 미팅 — {meeting-name}

   - 날짜: {YYYY-MM-DD}
   - 시작: {HH:MM}
   ```
4. `context.md`를 템플릿 기반으로 초기화 (비어 있는 상태로 생성하여 사용자가 채울 수 있도록):
   ```markdown
   # Context — {meeting-name}

   > 이 파일은 선택사항이지만, 채워두면 분석(meeting-review) 품질이 크게 향상됩니다.
   > 언제든 `/cap context ...` 로 추가하거나 직접 편집 가능합니다.

   ## 미팅 목적

   ## 참가자 (이름 / 역할)

   ## 프로젝트 배경

   ## 본인 역할 / 알고 싶은 것

   ## 관련 자료 (링크, 파일)
   ```
5. `~/meetings/.current`에 새 미팅 폴더의 절대 경로를 한 줄로 기록 (활성 미팅 추적)
6. **한 줄로 확인 + context 안내 한 줄**:
   ```
   📁 새 미팅 시작 — {경로}
   💡 배경 정보 있으면 `/cap context ...` 또는 자연어로 알려주세요 (선택)
   ```

### 모드 2: 새 슬라이드 캡처 — 메시지에 이미지가 있을 때

이미지 **유무**로만 판별. 텍스트가 같이 있어도 OK, 없어도 OK.

1. `~/meetings/.current` 읽어 활성 미팅 폴더 찾기
   - 없으면: `⚠️ 활성 미팅 없음. /cap new {이름}으로 먼저 시작하세요.` 하고 중단
2. 활성 미팅의 `images/`를 스캔해서 다음 슬라이드 번호 결정 (`slide-01`, `slide-02`, …)
   - **항상 디렉토리 스캔 기반**. notes.md 파싱 의존 금지
3. 첨부 이미지를 `images/slide-{NN}.png`로 저장
   - Claude Code가 이미지 경로를 노출하는 방식:
     a) 임시 파일 경로(예: `/var/folders/.../clipboard-*.png`)가 보이면 → `cp`로 복사
     b) 경로가 불분명하면 → 추측 가능한 가장 합리적인 경로로 시도 후 실패 시 보고
4. `notes.md` 끝에 새 섹션 append:
   ```markdown

   ## 슬라이드 {NN} ({HH:MM})
   ![](images/slide-{NN}.png)

   ```
5. **메시지에 텍스트가 같이 있다면** → 그 텍스트를 모드 3 로직으로 첫 발화로 즉시 추가
6. **메시지에 텍스트가 없다면** → 슬라이드만 저장하고 끝 (발화 섹션 없이)
7. 한 줄 확인:
   - 텍스트 있음: `📸 슬라이드 {NN} + 발화 저장`
   - 텍스트 없음: `📸 슬라이드 {NN} 저장`

### 모드 3: 기존 슬라이드에 텍스트 추가 — 이미지 없이 텍스트만

1. `~/meetings/.current` 읽어 활성 미팅 찾기 (없으면 모드 2와 동일하게 안내)
2. `notes.md`를 읽어 가장 마지막 `## 슬라이드` 섹션 위치 찾기
3. 그 섹션 끝에 발화 블록 append:
   ```markdown

   ### [{HH:MM}] 발화

   > {사용자가 보낸 텍스트 — 원문 그대로 preserve}
   ```
   - 사용자 텍스트가 여러 문단이면 각 줄 앞에 `> ` 를 붙여 blockquote로 보존
4. 만약 아직 슬라이드가 하나도 없다면 (`## 슬라이드` 섹션 없음): notes.md에 `## 메모 (슬라이드 없음)` 섹션을 만들고 거기에 추가
5. 한 줄 확인: `📝 추가 → 슬라이드 {NN}` 또는 `메모`

### 모드 4: 배경 정보 저장 — `/cap context {내용}` 또는 자연어 감지

**명시적 형태**: `/cap context 이 미팅은 일본 Payroll 팀 기술 리뷰고, 나는 한국 쪽 PM이야`

**자연어 감지**: 사용자가 "이 미팅은 ~에 대한 거야", "참가자는 A, B, C야", "배경: ~" 같은 문장을 보내면 **현재 활성 미팅의 context**로 판단.
- 판단이 애매하면 물어본다: "이걸 context.md에 저장할까요?"

동작:
1. `~/meetings/.current` 읽어 활성 미팅 찾기
2. 활성 미팅의 `context.md` 읽기
3. 적절한 섹션에 사용자 내용 통합:
   - 내용이 "참가자"에 대한 것 → `## 참가자` 섹션 아래 추가
   - 내용이 "목적/배경"에 대한 것 → `## 미팅 목적` 또는 `## 프로젝트 배경`
   - 섹션 판별이 어려우면 `## 기타 메모` 섹션에 append
4. 한 줄 확인: `📋 context 저장됨`

## 시간/날짜 표기

- 시각: `date "+%H:%M"` (24시간제, 로컬 시간)
- 날짜: `date "+%Y-%m-%d"`
- 모든 타임스탬프는 사용자의 macOS 로컬 시간 기준

## 활성 미팅 상태 추적

`~/meetings/.current` 파일이 단일 진실 공급원:

- 내용: 활성 미팅 폴더의 절대 경로 한 줄
- 새 미팅을 만들 때마다 덮어쓴다
- 사용자가 명시적으로 "미팅 끝" 같은 말을 하면 비워도 좋지만, 강제는 아님

## 응답 길이 (매우 중요)

미팅 중 모든 응답은 **1~2줄 이내**. 예시:

- ✅ `📸 슬라이드 3 저장`
- ✅ `📝 추가 → 슬라이드 3 (14:42)`
- ✅ `📋 context 저장됨`
- ❌ 캡처 후 긴 요약, 다음 단계 안내, 마크다운 미리보기

설명/요약은 `meeting-review`, `recap`, `ask` 같은 다른 스킬이 담당.

## 엣지 케이스

| 상황 | 대처 |
|---|---|
| `/cap`만 보내고 이미지/텍스트 둘 다 없음 | `❓ 캡처할 이미지나 텍스트가 없습니다` |
| 활성 미팅 없는데 이미지 보냄 | 모드 2 1단계 안내 |
| 한 메시지에 이미지 여러 장 | 각각 다음 번호로 별도 슬라이드 저장 (텍스트는 마지막 슬라이드에만 붙임) |
| meeting-name에 공백/한글 | 슬러그화: 공백→하이픈, 한글은 그대로 유지 |
| `notes.md`가 없는데 모드 2/3 호출 | 활성 미팅 폴더가 손상된 상태. 알리고 중단 |
| 사용자가 애매한 문장 보냄 (context인지 발화인지) | 짧게 물어본다: "발화(텍스트)로 저장할까요, 배경(context)로 저장할까요?" |

## 주의

- 슬라이드 번호는 **반드시 디렉토리 스캔 기반**으로 매긴다
- `~/meetings/.current`는 단일 라인 파일
- macOS 한정: BSD `date`, 경로 구분자 `/`
- **다른 스킬과 겹치지 않기**: 분석/요약 요청은 이 스킬의 책임이 아님 → `meeting-review`/`recap`/`ask`로 위임
